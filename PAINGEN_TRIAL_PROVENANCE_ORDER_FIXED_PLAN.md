# PAINgen trial provenance and rating-order audit: fixed plan

## Purpose and existing knowledge

The [condition-mean comparison](PAINGEN_INTENSITY_UNPLEASANTNESS_COMMON_INTERFACE.md) could not verify which trial ratings were paired or which was asked first. Inspect the study's released BIDS event files and compare their trial-level ratings with the condition-mean export. This is a **data-provenance and design audit**, not a pain-mismatch experiment, causal mediation study, analysis of raw MRI, new clinical finding or demonstration of subjective identity. It uses a published study and data already examined by this project; this plan is not prospective preregistration or outcome-blind discovery.

Before writing the plan we inspected the recursive trees of two dataset releases, the v1.0.1 README, dataset description and event sidecar, plus the complete event schema and event-class summary of **one v1.0.1 run**. We saw that its stimulus rows carry both ratings and subsequent intensity/unpleasantness events carry their respective values; in this one example intensity precedes unpleasantness on every trial. We did not inspect other run contents or calculate the sample-wide order, timing or source-reconstruction results. We know from the article and prior audit that authors describe randomized rating order; the sample-level implementation must be checked, not assumed from this example.

## Fixed sources and integrity

Use the paper-cited [OpenNeuro ds004746 v1.0.0](https://doi.org/10.18112/openneuro.ds004746.v1.0.0), GitHub mirror [tag 1.0.0 at commit `8a38ee30b870373547676bf0d0638e16160472a1`](https://github.com/OpenNeuroDatasets/ds004746/tree/8a38ee30b870373547676bf0d0638e16160472a1). Its complete Git tree was retrieved from the GitHub API and has 1,574 event paths; a preliminary tree-only comparison showed the later 1.0.1 release has the same 1,574 event paths and event blob hashes. This comparison does not establish equality of the remainder of the releases. Use the 1.0.0 tree and archive. Verify the API tree is not truncated and verify each event archive member's Git blob SHA-1 and declared byte size against that tree. Read no MRI or participant metadata. The v1.0.1 dataset description declares CC0; verify the v1.0.0 metadata rather than assuming the license is identical. Do not copy event records or participant identifiers into the repository; publish aggregate counters only.

The comparator is the authors' `merged_firstlvl_stim_betas_to_share.csv`, pinned and checked by [the existing cross-check](verification/paingen_source_crosscheck.py), commit `da46f2f9739ad2e9eeb9658711582be6357c1026`, SHA-256 `b40b4a1b1e001f2317fea07a49c6ee6de062f181a20affe149fe50a81b58545b`, 431,317 bytes. Its README defines `Yint`, `Yunp`, modality and coded level. Its participant/family identifiers are sensitive grouping data and must not appear in printed or written outputs. This is a same-study cross-export consistency check, not independent ground truth.

## Event parsing and stop rules

Audit all `_events.tsv` blobs rather than selecting a representative participant. Require the BIDS path to yield a participant, session and run; check unique paths and unique person/run combinations, but do not assume that every dataset person has all four runs. No demographic or family analysis is planned.

Use event file order only if finite onsets are nondecreasing and every row has recognizable `trial_type`. Otherwise mark the file **ambiguous**, exclude it from sequence-based reconstruction and count its reason. Treat equal onsets at distinct rows as ambiguous unless the order can be established without relying on file ordering; do not silently break ties. For each accepted run require exactly eight stimulus episodes, each consisting of a warning cue, one heat or press stimulus, then exactly one intensity-rating and one unpleasantness-rating event in either order before the next warning cue. Flag and exclude a run that cannot be parsed; count header-only or missing files. This deliberately conservative grammar may exclude interpretable events; it is a readiness screen, not a claim that excluded data are erroneous.

For each parsed episode compare each duplicated rating on the stimulus row with its respective rating-event value. Count complete equal, unequal, joint missing and one-sided missing values for each prompt, using absolute tolerance `1e-10`; malformed/nonfinite/out-of-[0,1] values are separately counted and are not converted to zero. Do not print an individual event or ID. A discrepancy is a cross-row data consistency flag, not by itself proof of the source of an error.

Report number of intensity-first and unpleasantness-first **recorded sequences**, counts of people with only either order and with both, and the corresponding number of valid prompts. These are reconstructed order positions, not proof that the randomization procedure worked or that either response caused the other. Analyze event durations (cue, heat, press, intensity and unpleasantness) using count, min, median, 25th/75th percentiles and max for finite positive values, count invalid separately. Recorded event duration need not equal physical delivery, thermode plateau, cue design setting or rating response time. Interpret any divergence from article descriptions cautiously and do not claim the data settle the real stimulus duration.

## Condition-mean comparison

Attempt only when both trial parsing and an unambiguous key can be established. Translate participants using the `sub-`-stripped BIDS ID *as written*, and compare its literal values against the source's `participant_ID`; do not infer hidden identity mappings or print identifiers. Fixed run-to-treatment rule: runs 01 and 04 are control, runs 02 and 03 placebo, following the source description. Fixed level mapping: heat `46.5/47/47.5` → `3/4/5`, pressure `3/4/5` → `3/4/5` **only if the observed codes and paper/README support it**; pressure event level is a coded field in this check, not a measured kg/cm². A different or ambiguous pressure mapping triggers a stop for that modality, not data-driven reassignment.

Within a source-condition key average all valid stimulus-row values separately for intensity and unpleasantness, using no imputation. Compare each reconstructed mean against the corresponding finite source `Yint` / `Yunp` within absolute tolerance `1e-10`. Count keys present on both sides, reconstructed-only, export-only, exact matches, mismatches, one-sided and joint missing outcomes; provide maximum absolute numeric difference when both are finite. Do not silently drop unsuccessful joins, duplicate keys or missing trials. If ID, condition code, run-treatment mapping or row semantics cannot be justified, explicitly stop and report the limitation rather than proclaiming successful reconstruction. Incomplete runs and ambiguous sequences can affect means; give the number of parsed episodes contributing to each mean as an aggregate distribution.

This comparison assumes source means were unweighted trial means and all relevant runs and trials were retained. Deviations are evidence that this provisional reconstruction and the export differ; they do not establish whether exclusions, transformations, missing values, run coding, earlier software or another cause explains the differences. Do not modify matching or exclusions after examining outcome values without an explicitly documented amendment.

## Interpretation

A valid reconstruction would support pairing and order **as recorded in the BIDS export**, not simultaneous experience during both questions, raw hardware timing, perfect report validity, an independently measured physical mismatch, subject individuation or metaphysical identity. Any sample-level order imbalance is descriptive and may reflect participant-level assignment or preprocessing; it does not itself establish a rating-order effect. Future order-effect analyses need a specified estimand, design-based assignment verification, correct grouping, temporal histories and family clustering, not a simple comparison of all trials as independent.
