# MEEG bounded signal and preprocessing audit plan

This is a retrospective, exploratory source-and-feasibility audit, not preregistration. Before this plan we read the MEEG paper's full arXiv v4 HTML prose, inspected the pinned repository README, parameters and preprocessing/cross-validation code, and streamed a **256 KiB compressed prefix** of its public example archive. We inspected only the gzip/tar headers and pickle opcode/array header, not signal values, labels or associations. The tar reports one `sample_1.dat` member of 306,688,410 bytes, with a pickle containing a little-endian float64 `data` array shaped `(20, 32, 59900)`. The first array payload begins in the prefix; `labels` was not reached. Do not execute `pickle.load`, whose format can execute arbitrary code. The GitHub example belongs to [commit `9136727`](https://github.com/xmh1011/AT-DGNN/tree/9136727e6a1d7370cf0cd8fbf057a7662efd17fc). Full example: 96,062,569 compressed bytes; full external MEEG dataset not obtained.

The next bounded analysis is to check whether the first trial's first channel can be decoded directly from the available prefix without decompressing the 306 MB member, using explicit pickle-header and length assertions and `numpy.frombuffer` only. Verify the archive prefix and tar/pickle framing, count finite samples and record a hash of extracted bytes, not the raw signal. Interpret channel Fp1 only provisionally, as the code's claimed original order, not a verified montage. Record no personal metadata or per-sample values in the tracked receipt. A prefix cannot authenticate the complete archive; cite the pinned Git blob and prefix hash, and scope results accordingly.

Then apply the exact pinned `notch_filter` and `notch_filter_per_channel` method bodies to (a) a synthetic 25 Hz + 50 Hz signal and (b) the first available signal, without running the repository's imports or unpickling. In both cases check exact input/output equality and whether standalone per-channel filtering changes the data. At `fs=1000,Q=50`, calculate the unassigned filter's notch-center interpretation under SciPy's `iirnotch` normalized-frequency default. Separately compute an explicitly specified, correctly centered 50 Hz notch on copies, just as a signal diagnostic, not as a claim that it produces a recommended preprocessing pipeline. Any before/after spectral summaries concern a single unverified channel, not affect or neuroscience evidence.

Check repository splitting code against the paper's trial-wise outer and nested-inner claims. Determine whether outer splits occur before or after flattening, whether normalization uses only outer training data, and whether inner validation and training share trials after flattening; construct a small synthetic fold witness rather than claiming to replicate the model. Note any discrepancy between the paper and code without assuming which version produced the published results. Do not call trial-wise within-subject cross-validation subject-independent, and do not infer that MEEG labels are actual individual felt reports: the paper's description says EEG was annotated based on the arousal and valence of the music, and actual label provenance has not been verified.

If source rights or provenance are uncertain, do not commit the binary prefix or individual data. Publish only audit code, tests and derived bounded summaries, and identify access limitations. Do not download the other 91 MB DEAP example or the full dataset. A single channel cannot determine network mismatch, subjecthood or an experiential bridge.
