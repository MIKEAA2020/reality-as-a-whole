# PAINgen trial provenance: post-inspection onset-order amendment

The [original plan](PAINGEN_TRIAL_PROVENANCE_ORDER_FIXED_PLAN.md) required event rows to be in nondecreasing onset order, otherwise excluding the run. The first run of the planned audit flagged **1,572 of 1,574** files as having decreasing source-row onsets, one for an unexpected row count and one for schema; **zero runs were accepted**, so no order, duration or rating/mean analysis was performed. This is a stop result, not evidence of 1,572 incorrect time stamps.

A subsequent bounded inspection of the same first run seen during planning found instances where the intensity event was listed before the unpleasantness event in the file even though its recorded onset was later. Therefore file position is unsuitable for reconstructing the reported order; the appropriate candidate is chronological sorting by recorded event onset. The result is still an interpretation of exported BIDS events, not independently validated timing. This amendment was written **after** observing the original failed-run counts and that one example, so the procedure is retrospective and no longer the original unamended plan. No rating-value associations or condition-mean reconstruction were examined before it.

For every file with the required schema, parse finite onsets and **sort rows by onset**. A tie among any distinct events is ambiguous and makes the run ineligible; do not break ties by file position. After sorting, require the same strict eight-episode cue → stimulus → one rating of each kind grammar. Count runs with source-row onset inversions separately from those accepted after sorting. All other original integrity checks, rating comparisons, conservative missingness rules and run/level mapping remain unchanged. Recorded onset order establishes event start order in this export only, not that one complete response finished before the other, or that participants were randomized independently per trial. Record the count of pairs in which the first rating's recorded onset plus recorded duration is later than the second's onset, and the counts with unavailable/nonpositive rating durations; overlapping event intervals are a further interpretive limitation, not grounds to reorder timestamps.

If sorting still leaves no valid episodes, stop the source-mean analysis and report zero eligible data. Any unsupported level or duplicate person/run continues to stop the run rather than induce a post hoc recoding. Outputs remain aggregate only.

## Later post-result diagnostic

The amended run found 610 intensity and 608 unpleasantness finite mean mismatches on overlapping keys, plus 307 export-missing keys per outcome. After seeing those results, add only an explicitly **post hoc diagnostic**: stratify overlapping condition keys by modality, treatment, and whether that person's four runs passed the parser; for each stratum count keys with both reported means equal, at least one unequal, and any source mean missing. Also count how often both dimensions differ versus only one. This does not change the mapping, tolerance, eligibility or earlier outcomes and cannot identify the cause of discrepancies. It tests whether the differences can be attributed solely to incomplete parsed runs or a single modality under this provisional join; it does not correct the source or the study.
