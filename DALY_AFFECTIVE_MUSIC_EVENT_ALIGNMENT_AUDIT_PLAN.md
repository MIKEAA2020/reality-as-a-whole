# Fixed audit plan: can affective-music events support a same-trial analysis?

This is a retrospective **format and feasibility audit**, not a prediction experiment or a preregistration. The paper and repository description and a single participant's run-2 event file and codebook have already been inspected; the result is therefore not blinded to the source's existence or example anomalies. The following checks were fixed before aggregate event-file counts were computed. No EEG, audio, extracted labels, or outcome–neural relations have been examined. We do not use inferred trial ratings for model fitting here.

## Pinned input and quantities

The source is the [OpenNeuro GitHub mirror](https://github.com/OpenNeuroDatasets/ds002721/tree/c0b784f902bb3dc6bd674e27feba5693b0fb9506), `c0b784f902bb3dc6bd674e27feba5693b0fb9506`. Read all matching `sub-*/eeg/*task-run[2-5]_events.tsv` files and the participant-specific run-2 codebook, with the repository's README and dataset descriptor. An event is a TSV row; `trial_type` is interpreted as an integer code and onset as seconds. Do not silently use the nominal `duration` field as music duration: compare paper and README.

For each run, count 788 music-onset rows, 786 fixation rows, and at each 788 onset distinct co-timestamp codes from the documented music-identity range **301–360**. Duplicate identical codes at an identical onset count once for identity resolution but are recorded. Exact equal onset is the criterion; separately report how often a code 301–360 occurs within ±0.1 s of a music onset. The 301–360 interval and 788 meaning come from the run-2 codebook, not selection from the results. Also count out-of-range codes 361–399 and 401–499 at or within ±0.1 s of music starts without assigning meanings to them. This is a conservative audit of the stated schema, not a claim that other codes cannot represent stimuli.

Partition each run into intervals from each 788 onset up to but excluding the next 788 onset; do not infer an end for a missing start. For each interval collapse identical `(onset, code)` events, then group events at exactly equal onset. Use the codebook's question codes 800–807 and purported answer codes 901–909. An interval has an **unambiguous strict same-onset questionnaire** only if, for each of its eight distinct question codes, exactly one timestamp has exactly one question code and exactly one answer code, and every other timestamp has no question code or answer code. The eight question–answer timestamps must be ordered after the corresponding music onset. Report counts of trials satisfying all these rules and of trials with each ambiguity type. Do not infer which answer belongs to which question from next-nearest onsets, keypress codes, event order or undocumented conversion behavior.

Additionally count values in the `duration` column and instances in which a 788 music onset lacks an immediately preceding 786 fixation in the previous 4 seconds. Count all runs and malformed data, do not filter by self-reported outcome or EEG artifact code. The expected 31 people × 4 runs × 10 starts is the paper's study description, not an inclusion guarantee.

## Decision and limits

A usable pairing of EEG, stimulus identity and individual self-report requires more than passing this structural screen. Even a complete strict screen does not demonstrate that codes or timing match the raw acquisition, that questions are displayed when their converted rows say, that onsets are accurate, or that the EEG is clean. A failure means this **particular conservative decoding** is not ready for use, not that the dataset lacks labels or that a more defensible decoder cannot exist. Do not use a relaxed decoder for a prediction study without independently checking conversion and documenting it.

A prospective, genuinely new test must fix the feature extraction, comparators, eligible participants, intervention or observational estimand, subject/clip holdout, reference handling and artifact criteria before seeing its EEG–report relationships. Here we have only accessible tabular event metadata; EDFs are git-annex symlinks and their data are not available on GitHub. The source repository includes conflicting dataset-license declarations (CC0 in `dataset_description.json`; CC BY 4.0 in its README); do not assume a resolution or republish trial records. Only aggregate counts and verification code will be tracked.
