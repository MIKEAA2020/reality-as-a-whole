# Fixed metadata-readiness plan: Rao intracranial stimulation and mood

## Question and prior inspection

Rao et al. ([2018](https://doi.org/10.1016/j.cub.2018.10.026)) and their [data record](https://doi.org/10.7272/Q6VD6WM2) describe intracranial recordings, direct brain stimulation, first-person mood reports and, in some patients, single-pulse probes. A [NEMAR BIDS conversion](https://github.com/nemarDatasets/nm000380) points to small metadata files and behavioral tables but says original pulse/stimulation times are not annotated, references and grounds are unspecified, and records include additional conversion limitations. Before this plan we read published metadata and inspected the GitHub tree's total path/type counts, not event rows or behavior values. The paper's earlier results are known, so this is retrospective and not preregistration.

The aim is **readiness**, not prediction. In particular, stimulus-evoked responses, observed phases and behavioral reports do not automatically identify a network's preferred interactions or the project's physical `q`. The candidate task is whether the released metadata provides enough unambiguous timing and linkage to even propose a valid analysis. If it does not, stop rather than infer missing times, manufacture a q or select examples until a desired outcome appears.

## Fixed bounded procedure

Pin NEMAR GitHub commit `c4fb7e96fb314b1c222ab9a826ce2a6e565ff6e6` and its untruncated recursive Git tree, plus its archive. Before loading content, calculate and record their SHA-256 and compressed length; then fix these in a checker. Verify each targeted ordinary Git blob by tree SHA-1 and byte size, and match the set of targeted paths. Inspect only `*_events.tsv`, `*_ieeg.json`, the two task-specific events dictionaries, `dataset_description.json`, and archive metadata necessary to locate these files. We will not parse participant demographics, brain signals, electrodes or raw behavior, inspect per-person outcomes, extract archive files to disk, run third-party analysis scripts, or save individual identifiers, timestamps or event rows. Output aggregate counts only.

For all events files: classify `task-stim` versus `task-sps`; count files, rows and distinct people; tabulate schema-column-name patterns, presence/absence/invalidity of onset and duration, and event-type values at an aggregate level only. Count runs containing any event label that could denote stimulation or a report using only exact schema values documented in the task dictionaries; unknown labels are kept as unknown, not interpreted from guesses. Validate unique dataset path and person/run keys. For event files and paired `*_ieeg.json` sidecars, count whether the original stimulus/pulse onset and offsets are documented as recorded, absent or ambiguous according to the sidecar and conversion notes; **no inference from synthetic BIDS onset zero**. If semantics cannot be decided from the source, report ambiguous rather than manufacture timing.

Count distinct people with stim files, with SPS files and with both, without printing IDs. Such a person-level overlap is only a prerequisite: it does not prove same contact pair, matching experimental block, or temporal sequence. Do not interpret `task-stim` as proven active versus sham without documented file-level attributes; do not infer continuous-time report availability from filenames.

If any target is missing, tree/archive hash or Git blob verification fails, target extension resolves to a pointer instead of intended content, event schema is inconsistent, or privacy rules cannot be met, stop and document rather than proceeding. A targeted count should be descriptive, not an estimate of effect or quality; leave all held-out prediction and invasive procedures unperformed. Data and behavioral tables remain in their existing external storage. Tests cover parsing and timing classification with synthetic data. A prior source-publication result is not an independent validation of a new mismatch model.
