# Fixed plan: bounded EEG–preference feasibility screen

## Purpose and known limitations

Before downloading or inspecting any participant MAT file, test the author's [Music-EEG dataset](https://github.com/AdamosDA/Music-EEG/tree/26f32cb4f087326a52fbf2e0b38e00630222be63). Its README states that 20 participants each preselected ten songs for each of three personal liking categories (1, 3, 5), then listened to randomized 80-second excerpts while EEG was recorded. Each participant file supposedly pairs `EEG_Songs` with `song_ratings` by song index. The ratings are **pre-recording music preferences**, not reports of momentary pleasantness, suffering, or felt emotion during the recorded trial. No shared song identities, audio, acoustic features, exact cue timings or original raw recordings are identified in the inspected repository; these are not implicitly available. The files are already filtered and artifact-cleaned; this analysis cannot reverse that preprocessing. The repository has no explicit data license file or declared license in its metadata. We will attribute it and not redistribute raw signals or individual trial tables.

This prospective-to-the-MAT-files feasibility plan is **not externally preregistered**. The source README and MATLAB demo are already read; the latter includes high/low PSD exploration and an illustrative SVM. The linked original paper's abstract is known; no other prior results of this dataset have been independently verified. Our screen is not a claim of novelty for EEG liking correlations and is not a reproduction of the published cross-sensor PAC method.

## Bounded access and inclusion

Download **only four files**, participants 01–04, sequentially, each approximately 34.4 MB; stop earlier on any failed hash, access or schema check. Do not fetch all 20 together. Read one at a time and retain no source files outside ignored `.arena`. Each file must match the pinned Git blob's SHA-1 calculated as Git `blob <bytes>\0<content>`. Verify array shape, finite values, sampling rate 128 Hz, 14 channels, 30 EEG trials, exact 10/10/10 category counts, sensor names, and rating vector length. Require usable F3/F4, F7/F8, AF3/AF4. If any check fails, stop instead of silently excluding or revising rules. Present any missing subject as a blocker, not a full four-person result. Trial pairing follows the source's aligned array contract; file checks cannot establish acquisition/log correctness.

## Fixed descriptive neural features

Use each song's full trial, common-average re-reference all 14 channels, derive one alpha-band phase time series per channel using a fourth-order Butterworth 8–13 Hz zero-phase SOS filter and the Hilbert analytic phase. Exclude the first/last five seconds, then partition the 70-second remainder into fourteen nonoverlapping 5-second windows. For each window and three left–right pairs `(F3,F4)`, `(F7,F8)`, `(AF3,AF4)`, calculate `PLV = |mean exp(i(phase_left−phase_right))|`; average the 42 values to obtain one trial-level **alpha phase-dispersion index** `1−mean(PLV)`. This is a descriptive signal statistic: it is not a channel-preference lag, identified physical frustration, conflict, negative affect, or experience. Small amplitudes make phase estimates unstable; signal quality, field spread, common reference, common drive and preprocessing all matter.

For comparison, obtain mean Welch 8–13 Hz band power at F3 and F4 on the same cropped data and use `log(power_F4)-log(power_F3)`. Use Hann 2-second segments, 50% overlap, constant detrending, and integrate at frequencies in `[8,13]`. Also calculate mean log Welch 15–30 Hz power over the same bilateral pairs as a non-relational spectral control. The statistics are subject to the same limitations and no sign is presupposed. Repeat all three features under the file's native reference, **without claiming that the native reference is known**, as a sensitivity check, not independent confirmation. Use a fixed tiny positive power floor only to avoid log zero; fail on nonfinite features.

## Estimand and no overclaim

For each feature and reference separately, calculate per-participant `mean(feature | rating=5) − mean(feature | rating=1)` and Spearman correlation with the 30 ordinal ratings; show per-person values and the unweighted four-person mean, if all four files pass. Do not pool windows or songs as independent people and do not report formal p-values from this small exploratory group. Repeated songs, shared stimulus structure, prior preference, motion, recording quality, music familiarity and subject/context can confound these contrasts; the two extreme groups were selected by prior liking, not randomized. No feature is a physical mismatch assay. A direction difference under reference changes weakens robustness, but its absence does not prove neural origin or causal specificity.

For prediction, the design forces 10 trials in each category, so a fixed prediction of 3 yields **MAE 4/3 and RMSE sqrt(8/3)** on the complete 30 trials; this is a descriptive in-sample category-balance reference, **not** a deployment benchmark or an independent prediction test. Do not fit supervised models or optimize features on these four participants in this screen. For a future decisive test, freeze variants, use unseen-participant/person-specific appropriate splits, control identifiable song/acoustic features, and obtain independently defined physical interaction preferences plus contemporaneous felt-affect reports. A predictive improvement would still not establish experiential identity.

Use standard-library Git blob verification and NumPy/SciPy feature code; no pickle execution. Tests must include synthetic constant phase differences (PLV one), nontrivial changing phase difference, reference effects and schema failure. Record exact hashes and software versions. Stop if licenses, provenance, source alignment or event timing cannot be adequately established for any stronger claim.

**Format clarification after the first file's structural preview, before reading signal values or ratings:** the MAT file is HDF5/v7.3, not SciPy's older MAT format, so use `h5py`. HDF5 exposes the dimensions reversed, `(time, sensors, songs)`, and its sensor names are lowercase and sometimes space-padded; normalize those names with trim and case-fold solely for the preselected pairs. Neither the feature definition nor the analysis target changes.
