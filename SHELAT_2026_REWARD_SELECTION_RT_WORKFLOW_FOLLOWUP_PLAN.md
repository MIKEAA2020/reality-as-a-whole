# Retrospective plan: reward versus selection, response time and R workflow

The article, results, scripts and earlier independent accuracy fits are already known. This plan is retrospective; it fixes the next analyses before calculating the new RT results and contrasts, not before learning any published result.

1. Trace the authors' test-phase response-time and trigger-by-distractor formulas, the relevant filters and factor coding. Load only the hash-checked learning/SART files required for these analyses, not survey records. Preserve participant IDs and trial records only in memory and never save them or trial-level residuals.
2. Fit a pooled random-intercept Gaussian response-time model `rt ~ distractor_feature * trigger + (1 | subjectID)` using the retained fast/slow records, as in the reviewer script, and compare the reward-versus-neutral coefficients with reported results. Separately compute direct **reward minus selected-unrewarded** and reward minus neutral contrasts within each trigger, with uncertainty. Use the same correct/incorrect-trial filtering as the original test dataset; document exact likelihood, approximations, package and coding differences, diagnostics and any discrepancies.
3. Reuse the previously fitted full accuracy model for planned conditional reward-minus-selection contrasts at the block midpoint 2.5, separately for fast and slow, with model-based 95% Wald intervals and an explicit slow-minus-fast contrast. Also retain observed-block estimates already calculated. These are a posteriori, unregistered pooled estimates, not tests of preregistered predictions; separately look at individual experiments without conflating significant with nonsignificant results. No multiple-testing correction is claimed.
4. Compare behavioral estimates, exclusions and interpretations to distinguish what the archived task supports from warning, selection history, speed–accuracy and neural recoupling mechanisms. A statistical association or absence of one does not identify subjective state or experiential unity.
5. Attempt a safe, limited R/lme4 workflow if obtaining dependencies is feasible; inspect before execution, do not execute original archive wholesale, and compare data inclusion, factor coding, fits and diagnostics. If unavailable, record the concrete failure and do not conflate independent Python fits with original execution. Verify calculations and update reports/inventories, keeping only aggregate outputs and checks.
